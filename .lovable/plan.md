### Technical details

- AI provider: existing Lovable AI Gateway via `koko-chat` edge function. Adds new intents `lesson` (rewritten), `qa` (rewritten), `project`, `assess`. Model stays `google/gemini-3-flash-preview`. Single edge function, branching by `intent`.
- Edge function reads JWT via `getClaims()`; pulls `profiles` row server-side so prompts can't be spoofed by client. Mission metadata (title, description, career) is still passed from client because it comes from static `userState.ts` data.
- `mission_lessons` schema:
  - `user_id uuid`, `mission_id text`, `lesson_md text`, `completed_at timestamptz`, `learning_signal text`, unique on `(user_id, mission_id)`.
- `mission_projects` schema:
  - `user_id uuid`, `mission_id text`, `brief_md text`, `submission text`, `assessment_md text`, `submitted_at timestamptz`, unique on `(user_id, mission_id)`.
- All public tables get `GRANT` block + RLS policies scoped to `auth.uid() = user_id`.
- Auth pages: enable Google provider (`configure_social_auth`); email confirmations stay on (no auto-confirm).
- Routes gated by an `<AuthGate>` wrapper on `/`, `/roadmap`, `/skills`, `/profile`, `/settings`, `/career`, `/mission/*`. Unauthenticated users redirect to `/signin`. Landing + assessment + sign-in/up remain public.
- Onboarding writes `{ name, age, education_level, career_path }` to `profiles` after the existing flow completes.
